# M2 validation on macOS ARM64 — 2026-11-20

M2 is **not accepted** by this run. Native and browser checks pass where
reported below, but the conformance registry rejects the current P02 contract,
keyboard-opened native dialogs lose their initial focus, and default browser
dirty-world rendering exceeds the performance budget in all three runs.
Remaining platform gates are open.

## Native interaction and remaining gates

The initial Mac permission preflight denied Accessibility/input access. After
the user enabled it, both `AXIsProcessTrusted()` and
`CGPreflightPostEventAccess()` returned true, and native CGEvent input ran.
The CPU sequence completed 20 checks, with one additional initial-focus failure.
Actual pointer input exercised confirm, cancellation, repeat/no-op and decline;
the red window-close button exited the process with status 0. A fresh console
submission completed through Tab/Space, and a foreign-unit request was rejected
without disclosure or effects. Native menu selection, Command+Enter, Command+G,
checked state, text-entry isolation and Escape cancellation passed. Dispatcher
ticks continued while the native View menu was held open over a pending decision.
The actual native file panel also kept dispatcher work moving; Escape cancelled
selection and returned focus to Import. This does not establish deadline/peer
delivery inside native tracking or every file-panel failure mode.

The extended Native AOT run completed 29 checks plus the recorded focus failure.
Fullscreen entry/restore used native menu Accessibility actions; ordinary menu
tests used pointer clicks. The restored dialog still accepted Escape without
effects. Native open/save panels imported and exported an authored 131,077-byte
file exactly. Preferences and the file survived a fresh application process;
removal then completed. All three AOT sessions exited 0 through the native red
close button. See `native-input-aot-cpu-tab-assisted-accessibility-fullscreen/`.

**Initial keyboard focus fails:** launch the Mac host, focus the console and
press Enter on `unit.stack-bottom unit=0:100`. The confirmation appears with
all three hit regions reporting `focused: false`; waiting does not restore it.
Space leaves the command at `AwaitingInteraction` with zero effects. Tab focuses
Confirm, and Space then completes once with one effect. Keyboard Enter on a
selected map unit also opens an unfocused dialog on CPU and GPU; Tab then restores
Escape cancellation. The console case was reproduced on managed CPU/GPU and
Native AOT. The original failing receipt is retained;
later Tab-assisted runs record the focus failure separately and still exit
nonzero. See `native-input-cpu/report.json`,
`native-investigation/console-enter-state.json`,
`native-investigation/dialog-tab-state.json` and
`native-input-cpu-tab-assisted-final/report.json` under the evidence root.

The [platform checklist](../testing/platforms.md) still requires complete native
tracking with deadlines/peer work, remaining file-selection failure paths,
physical mixed-DPI transitions, IME, screen readers, physical audio
and device interruption, and Safari/Firefox execution. Hardware performance and
physical presentation remain separate from software-raster correctness.
Full M2 also retains its other-platform and live-provider gates.

## Hardware browser performance failure

The default CPU composer with hardware WebGL presentation used
`ANGLE (Apple, Apple M4, OpenGL 4.1)` at physical 1920×1080, 1× density.
The authored large-world workload ran at full detail with dirty-world changes,
30 warmup frames and 300 measured frames in each of three runs. Other validation
workloads had completed before timing. All 309 compiled inputs matched the
checkout. Raw samples are in `performance-browser/performance.json`.

| Run | Frame work p50 | p95 | p99 | Maximum | Target |
| --- | --- | --- | --- | --- | --- |
| 1 | 71.335 ms | 72.855 ms | 74.010 ms | 74.965 ms | Failed |
| 2 | 70.595 ms | 72.360 ms | 73.455 ms | 74.505 ms | Failed |
| 3 | 70.830 ms | 72.385 ms | 73.345 ms | 73.580 ms | Failed |

The [contract](../performance/map-rendering.md) requires p95 ≤ 16.7 ms and
p99 ≤ 33.3 ms for this workload. The benchmark completed without driver errors;
its process exit status does not indicate budget acceptance.

Frame work measures map-renderer entry through Skia lease disposal, adding
authored mutation, projection and scene binding for dirty updates. Lease
acquisition and other host work are excluded, so even this partial boundary
exceeds the budget. Input-to-rAF p95 was 144–147 ms, but this is a driver/browser
observation, not physical presentation latency. GPU timer queries were
unavailable. No physical scanout or native-desktop timing acceptance is claimed.

All three sampled endpoint images exactly matched fresh frames after timing.
The driver does not compare every timed frame; effects, other resolutions/detail
levels, native timing and remaining performance workloads retain their own gates.
The repeated failure is retained without relaxing the target.

## Reproduction and setup corrections

Use the repository's [build instructions](../BUILDING.md),
[map matrix](../testing/map-rendering.md), [platform checklist](../testing/platforms.md)
and [performance protocol](../performance/map-rendering.md). The local
`build/m2-macos/run.py` selects the isolated SDK, Python environment, NuGet cache
and Playwright installation and records each command. Content roots are
`build/m2-macos/content/assets` and
`build/m2-macos/content/fonts/dejavu-fonts-ttf-2.37`.

Initial sandbox DNS and MSBuild-server attempts could not run. Network setup and
host builds subsequently ran with normal local access; the build used
`--disable-build-servers -m:1 -p:UseSharedCompilation=false`. Two initial asset
validator invocations used unsupported option combinations; the corrected
separate asset/font checks passed. The first AOT startup receipt used the
managed identity validator; validating its same saved identity with
`native_aot=True` passed. Native-driver follow-ups corrected modifier release
and moved focus out of the console before testing its intentionally suppressed
accelerators. Fullscreen's auto-hidden menu supplied zero-size item bounds to
the pointer driver, so entry/restore was subsequently verified through native
menu Accessibility actions. These driver/setup errors are retained in the logs
and are distinct from the conformance, initial-dialog-focus and performance failures.
