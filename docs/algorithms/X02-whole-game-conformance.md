# X02: Whole-game conformance

Target: classic Civilization II Multiplayer Gold Edition
**5.4.0f, patch 3**, under [X01](X01-classic-compatibility-contract.md).

This document specifies how to capture, replay and compare the behaviors in the
algorithm collection. It owns the fixture format, comparison procedure, coverage
ledger and integration plan. It does not redefine game mechanics or claim that
an implementation passes them. The three supplied fixtures are
small specification vectors, not recordings of a complete original-game run.

[F01](F01-determinism-and-arithmetic.md) owns arithmetic, sampling laws and implementation reproducibility;
[F02](F02-game-state-and-invariants.md) owns logical state and identity. Each
algorithm owns its operation boundaries and observations. Original record sizes,
addresses and platform adapters belong to those documents' evidence appendices.
An implementation can use different storage and still produce this format.
[X01's ordering rule](X01-classic-compatibility-contract.md#behaviorally-significant-ordering)
also permits equivalent internal evaluation. Compare required semantic events
and their dependencies, not incidental helper/store order. A reference sequence
remains the default where independence has not been established.

## 1. Claims and test boundaries

A conformance claim names an operation or scenario, input domain, implementation
revision, specification revision, environment and comparison surfaces. A passing
boundary case establishes only those observations under those inputs. It does
not establish its caller, omitted children, other modes or unrecorded failures.

Use these distinct case levels:

| Level | Start and stop | What it can establish |
| --- | --- | --- |
| Primitive | One registered operation with complete read state | Arithmetic, query, mutation or local selection contract |
| Subsystem | Actual parent plus declared children; list every supplied child | Ordered effects within that composition |
| Integration | Actual participating subsystem implementations; external providers controlled | Behavior across the named joins, including callbacks and failures |
| Session | Startup/load through commands, turns and shutdown or another explicit boundary | Those session histories under the recorded environment |

Evidence kind is independent of case level. Distinguish original instructions,
original observations, independent reconstruction agreement, specification
vectors, and deliberate policy tests. A source-body fixture with supplied device
callbacks is not native original playback. A test whose expected output was
generated by the implementation under test is a regression case, not an
independent oracle. Record that provenance even if all comparisons pass.
An original observation can exercise any of these levels; it establishes its
measured surfaces, not an assumption about unmeasured state. In JSON, levels are
the lowercase strings `primitive`, `subsystem`, `integration` and `session`.

Input profiles distinguish required support from optional extended acceptance:

- **Nominal:** intended inputs and supported custom content. Stock values are
  only one subset. Preserve scalar wrap reachable from ordinary play.
- **Accepted off-nominal:** optional additional acceptance of specifically
  recovered unusual inputs. Once claimed, preserve their interpretation, defined
  errors, scalar wrap and relevant partial effects. The pure F01 mapping vectors
  can exercise such domains without requiring an importer to admit them.
- **Restricted:** required safe-policy coverage for declared rejection outside
  nominal support, including malformed or unsupported content. A documented
  prevalidation/transactional rejection may differ from original partial parser
  mutations. Do not reject nominal custom scenarios or normal fragmented TCP
  delivery under this label. Repairs beyond documented normalizations need their
  own declared conversion policy.

Every profile excludes out-of-bounds writes and corruption. Tests may record an
original defect as evidence, but must never require the cleanroom implementation
to reproduce it, including by assigning the corrupted adjacent logical fields.
The owner specifies safe omission, rejection, capacity growth or a bounded stop.
Unknown reads affecting required behavior need supplied evidence or a stop;
UI-only stale buffers may be initialized/eliminated under X01. No simulation
read gains a universal zero value from the presentation relaxation.

### Required semantics and optional reference fidelity

Apply X01's [presentation](X01-classic-compatibility-contract.md#presentation-and-semantic-interaction-policy),
[UI-failure](X01-classic-compatibility-contract.md#harmless-native-ui-failures),
[input-admission](X01-classic-compatibility-contract.md#input-admission-and-rejection-policy)
and [transport](X01-classic-compatibility-contract.md#required-and-optional-transports)
policies to every owner and case, including historical mandatory-looking lists.

Required UI fixtures register semantic operations: inspect information for an
observer, choose an identified option/target, edit a value, accept, cancel, skip
or receive a timeout/remote result. Compare information values, authored content,
visibility, availability, committed changes, command/result encoding and required
ordering. The adapter maps native or redesigned controls to those operations.
It must not hide a game mutation or invent an operation that the tested UI cannot
actually perform. Raw screen coordinates and widget return numbers belong only
to an implementation-specific adapter or optional original-presentation test.

Use the owners' main sections for required semantic operations. Their **Original
presentation reference** appendices preserve optional native/raster procedures;
register those checks separately. Keep any layout-dependent simulation admission
in the semantic fixture's logical inputs, independent of the new renderer.
Relocating a paragraph does not turn source-image/export bytes or game-state
mutations into optional comparisons.

Original pixels/fonts, audio samples, window/control geometry, repaint/native
pump traces and cosmetic randomness are optional reference comparisons. Record
that purpose in the operation registration, comparison scope and evidence limits;
they cannot block a baseline semantic conformance claim. Conversely, cosmetic
agreement cannot replace information/privacy, command or gameplay checks. Use
existing `effect` events for semantic notices/choices and required outcomes;
no fixture-format or wire-protocol extension is needed.

Required mixed-peer sessions use original TCP/IP with UDP discovery and both
host roles. IPX/SPX, modem/serial and legacy launch-lobby/provider tests are
optional extension coverage, not missing baseline cases. Required negative tests
show clear safe rejection/cleanup outside supported input and harmless UI failure
handling without lost committed edits or required replies. Compare original
malformed-input/native-failure traces only when that additional behavior is claimed.
AI heuristics, map generation and simulation numeric expectations are unchanged.

## 2. Version 3 fixture format

A fixture is one UTF-8 JSON object with format `openciv2-conformance/3`. It may
reference binary blobs by hash, but never executable original code. Small binary
values can be inline hexadecimal. File extension is `.json`; repository examples
use the `X02-` prefix. Readers reject duplicate object keys, unsupported format
versions, invalid typed values and unrecognized required fields. Additional
metadata is allowed only in an `extensions` object and cannot change semantics.

| Required top-level key | Value and meaning |
| --- | --- |
| `format` | Exact format identifier above |
| `id` | Stable, nonempty case ID; a changed expected result creates a new revision |
| `revision` | Positive metadata integer, increased for any semantic fixture change |
| `target` | Object with `game`, `version`, `originalImageSha256`; an image identity is a target identifier, not a claim it was executed |
| `specifications` | Array of `{id,file,sha256}` for all contracts used; paths relative to the fixture directory, hashes of the exact file bytes |
| `boundary` | `{level,operation,start,stop,arguments,suppliedChildren}`; level from §1, operation registered as below, arguments a named value map, suppliedChildren an explicit array |
| `profile` | `{domain,safety,restrictions,deviations}`; domain is `nominal`, `accepted-off-nominal` or `restricted`; the last two are arrays of explicit statements |
| `entry` | `{state,retainedInputs,blobs}`; complete declared read state, separately evidenced incoming reads, and external binary inputs |
| `randomness` | `{mode,policy,contexts,choices}` as defined below; never inferred from a seed alone |
| `environment` | `{protocol,inputs,unexpected}`; protocol `scripted-v1`, ordered request/input records, unexpected=`fail` |
| `expected` | `{outcome,result,state,trace}`; outcome and event format in §§4–6 |
| `comparison` | `{stateScope,traceKinds,order,exclusions,normalizations}`; state scope plus the dependency contract in §6 |
| `evidence` | `{kind,sources,limitations}`; independent evidence provenance and finite validation limits |
| `limits` | Positive metadata integers `events`, `providerRequests`, `hostMilliseconds`; harness bounds, never game-clock inputs |

Metadata integers are JSON integers in 0..2147483647, with positive values where
specified. Game scalars use §3's typed values instead. Arrays are ordered except
for explicitly keyed choices and the dependency comparisons below. Trace arrays
still record chronological order. Objects are maps with case-sensitive keys; their serialization order has no game meaning.
Reject trailing non-JSON data. Hashes use lowercase SHA-256 hexadecimal. For raw
fixture identity, hash the exact UTF-8 file bytes; formatting changes can therefore
change that hash without changing its parsed meaning. Record both fixture ID/
revision and hash in a run report. Do not invent a universal hash of native memory.

### Operation and state registration

An operation ID is `OWNER.name`, for example `F01.primaryModuloFromCode`. Its adapter
registration records: owning document/anchor, argument names/types, result type,
read/write state closure, ordinary preconditions, callback opportunities and
stop boundaries. It also defines stable invocation/event identities, required
observation boundaries and dependencies, and the domain and evidence for each
claimed independence. Include aliasing, actual callbacks, accepted faults and
partial effects. A fixture cannot weaken those obligations by omitting an edge.
Registration maps to an implementation entry; it does not prescribe a public function name or source layout. Two implementation entries
implementing the same operation share the contract, not an address.

State keys are stable owner-qualified names, such as `F01.randomContexts` or
`F02.units`. Their registry states value type, lifetime, collection order and
cross-reference rules. A composite fixture must use the same key for the same
shared state across parents and children. Keep city caches shared where required;
random contexts follow the implementation's declared partition, not the old
globals. The owner table in §8 routes new registrations; each owner's
main text supplies the actual field meanings and operations.

The included vectors register `F01.primaryModuloFromCode` with i32 `code`/`n`
arguments and `F01.secondaryRangeFromCode` with i32 `lo`/`hi` and u32 `U`.
Both return i32 and are pure mappings with empty state closure. Their invocation
is `root`; selected event IDs are `root.enter`, `root.return`, `root.exit`, with
dependencies enter → return → exit and no independent pair. No external
calls or supplied children are permitted. Codes are explicit arguments, not
PRNG seeds; these vectors do not exercise sampling or a generator. General
registrations must enumerate their larger closure.

### Randomness modes

`randomness.mode` is one of these three strings:

- `controlled-choices`: `policy` is null, `contexts` is an empty object, and
  `choices` is an array of semantic decisions keyed by `(site,call,attempt)`,
  with no duplicate keys; array position does not impose a global sample order.
  Each record has `id`,
  `site`, `call`, `attempt`, `law`, `arguments`, `code`, `result`. IDs/site/call
  are nonempty strings; attempt is a nonnegative metadata integer. Site and
  attempt identify the owner's operation/candidate/round, not a raw RNG call
  index. Arguments, code and result are typed values. Laws are `primary-code`
  (i32 code 0..32767, no arguments, same result), `primary-modulo` (same code,
  i32 positive n, result code%n), `secondary-unit` (u32 code, no arguments,
  f64 result), or `secondary-range` (u32 code, i32 lo/hi, i32 result). Derive
  the result by F01, validate any recorded result against it, and inject at
  the named site. Equal bounds and unused samples require no choice record.
  A pure mapping with a code argument, as in §7, has an empty choice list.
- `implementation-replay`: `policy` is `{id,version,sha256}`, identifying a
  documented generator/sampling/stream/key/scheduling policy; id and version
  are nonempty strings. `contexts` supplies its complete typed initial state,
  including keys/counters needed for continuation. `choices` is empty: actual
  samples are generated. Expected final contexts appear as the registered
  `F01.randomContexts` state, and decision traces retain policy-local context
  identities. Compare only runs under the same policy/version; sampler-law
  validation is an additional obligation.
- `legacy-reference`: `policy` identifies a pinned original-sequence adapter,
  `contexts` supplies original S/N and any additional captured inputs, and
  `choices` is empty. Apply F01 Appendix D, including discarded samples and
  presentation sharing. This mode is optional evidence, never a requirement
  for cleanroom conformance or a substitute for implementation replay.

Original-game interoperability tests are required independently of these modes.
Using an unmodified original peer does not make a case optional `legacy-reference`:
that mode means exact original random-sequence emulation. For a mixed-session
`implementation-replay`, capture the new engine's own contexts and the incoming
original-peer messages/results as external inputs. Record that peer's executable
identity and capture provenance, but do not require its private RNG state or
policy-version negotiation. Replaying a captured peer transcript alone does not
establish a new live interoperability run.

For replay modes, entry `F01.randomContexts` must equal `randomness.contexts`;
its registered schema comes from the policy. Controlled-choice fixtures omit
internal random contexts from both entry and expected closure: they compare
semantic decisions, not unrelated internal representations. They may exercise
real parents/children at any case level and establish their conditional behavior;
they do not prove generator quality or seeded reproducibility. Random injection
is an input boundary, not a supplied gameplay child.

Look up each mandatory choice by site, call and attempt, then match law and
arguments; consume each keyed record once. Missing, duplicate, unused mandatory
or mismatched choices fail as unexpected input. No fallback randomness.
Eliminated unused samples are absent from this semantic trace. Preserve significant
queries/callbacks around a sample through §4 even when its value is unused.
Owner adapters must distinguish those effects from a raw PRNG request. Do not
turn a pure internal query into an arbitrary mutating provider to impose order.

### Migration from earlier formats

Readers do not silently accept versions 1 or 2 as version 3. Version 1 required
original states and draw traces implicitly. First migrate it to an explicitly
optional legacy case, or to a reviewed controlled-choice case with new
expectations and no original-state comparison.

For version 2, register stable semantic invocation/event IDs and add
`comparison.order`. Start with a chain retaining the selected reference order.
Remove incidental helper observations only after reviewing the owner's semantic
boundary, and relax an edge only with the independence declarations required by
§6. Retain required events, values, identities, callback nesting and partial
failure prefixes. Increase the fixture revision, update specification hashes
and record the conversion's provenance. Historical validation reports are not
version 3 execution evidence; migration does not establish a new gameplay run.

### Blob descriptors and paths

A blob descriptor is `{id,path,sha256,length,role}`, where length is a canonical
unsigned decimal string and role identifies rules, asset, save, packet, pixels,
audio, or provider output. Resolve paths under the fixture bundle root; reject
absolute paths and parent traversal for blobs. Specification paths may use `..`
only within the declared repository root. Hash/length mismatches invalidate the
fixture before execution. A missing copyrighted asset is `unavailable-evidence`,
not a skipped passing case. Assets can stay external to the public repository;
an explicit local resolver maps hash to a privately supplied copy.

## 3. Logical values and complete entry state

Typed scalars are objects with `$type` and `value`, except the explicitly listed
forms below. The `$type` key is reserved; ordinary record maps cannot use it.
Untyped game numbers, booleans and strings are invalid. Ordinary objects contain
named values and arrays contain values recursively.

| `$type` | Canonical representation |
| --- | --- |
| `u8`, `u16`, `u32`, `u64` | `value` is unsigned decimal text in the exact range; no plus sign or redundant leading zero |
| `i8`, `i16`, `i32`, `i64` | Signed decimal text in range; no negative zero, plus sign or redundant leading zero |
| `bool` | `value` is JSON true/false; only for a genuinely boolean logical field |
| `text` | `value` is Unicode text, without implicit case folding or normalization |
| `bytes` | `hex` is an even-length lowercase hexadecimal string; no `value` |
| `blob` | `id` selects an entry blob; `offset`/`length` are canonical unsigned decimal strings describing an in-bounds byte range |
| `f64` | `bits` is exactly 16 lowercase hex digits denoting the binary64 bit pattern, most-significant digit first; no decimal conversion |
| `ref` | `space`, `id` are nonempty symbolic strings; optional `slot`/`token` are typed integers when the owning identity has those components |
| `null` | Only `$type`; explicit absence, distinct from numeric sentinels or empty text |
| `unavailable` | `reason` states missing evidence; optionally `evidenceId`; cannot be consumed as a value |

If F01 requires an extended floating intermediate at a captured boundary, encode
its sign, exponent and significand in an owner-defined record and identify its
precision/rounding environment. Do not round it to f64 for convenience. Ordinary
f64 bit strings distinguish negative zero and NaN payloads where an owner makes
them observable. Integer signedness is part of the comparison, not merely a
printing choice. Original field widths that affect behavior belong in the
registry even if the implementation uses arbitrary-precision integers. These
fixture tags describe canonical logical values at the comparison boundary,
not the implementation's field types. Compare through the owning conversion;
do not require native storage-width introspection or extra trace events for
eliminated internal casts. F01 permits equivalent evaluation of unobserved
intermediates. Keep required publication/callback boundaries and failure results.

For a bounded quantity, record its semantic range and sentinels in the owner
registry, separately from its fixture encoding. A redundant-reduction case may
compare the wider calculation with reference evaluation at required boundaries.
Include significant wrap/signed-view cases and reachable custom-content values;
label unsupported-input reference cases by their optional profile. A passing
stock-data sample is not a proof that a width-dependent effect is unreachable.

Text bytes at file/protocol/font boundaries remain bytes with a separately
declared encoding. `text` is appropriate only after the owning conversion.
Unterminated original strings need bounded bytes, not a JSON string that
silently supplies the missing terminator.

Capture all state that may be read before a defining write, including through
callbacks or aliases. F02's layers are process, session, world, retained derived
state and operation workspace. Include mode-appropriate random inputs, token generators,
scan bounds, holes and payload of retained slots when relevant; actor, observer,
human mask, authority and resume identity separately; map seed/topology/knowledge;
rule tables and mutable cursors; queues, dirty flags, cached costs and shared
selection/dialog/media state. A save file is not a substitute for those inputs.

Preserve array/slot/stack/route order and reused-slot lifetime tokens. Do not
compact holes, repair stacks, recalculate cities or discard stale caches during
fixture installation unless that operation is part of the tested entry. Check
invariants only at the owner's stated stable boundaries. Transient state during
loading, relocation or callbacks may deliberately violate a final invariant.

`retainedInputs` is an ordered array of `{id,consumer,value,origin}`. Consumer
names the operation and exact first-read boundary; origin records backing or
the original observation supplying it. Installing a retained input does not
initialize unrelated fields. Shared/overlapping **valid** input storage uses
one logical storage ID plus views, so later valid writes affect later reads.
Native addresses are evidence metadata only. An invalid read can be supplied
for a bounded conditional comparison; its address cannot authorize an invalid
write or redefine the destination object's bounds.

For `complete-boundary` stateScope, the registered closure must be covered by
entry values, documented producers, and expected final values. Missing inputs
are invalid before execution when statically known; otherwise stop on first
consumption after retaining preceding effects. A `projection` case must name
excluded state and reasons and claim only that projection. “Everything else
unchanged” is valid only when entry and expected registries actually cover it.

## 4. Ordered environment inputs and reentry

`scripted-v1` retains the order of actual external requests and deliveries.
Internal independence does not relax this script, wire/file ordering, command
authority or required synchronization. Pure internal queries need no scripted
provider; omitted/cached helper evaluations are not unexpected external inputs.
A supplied-child case may intentionally exercise a particular callback schedule,
but cannot invent callbacks inside an otherwise pure operation and promote that
schedule to a general compatibility requirement. Register genuine reentry
opportunities from the owner. Version 3 adds no unordered-provider protocol.

Scripted environment inputs are consumed in listed order. Each record contains
`id`, `request`, `arguments`, `actions`, `result`. Request is a registered provider
operation; arguments/result use §3. On an unexpected request, wrong arguments,
wrong order or an exhausted script, stop as `unexpected-input`. Never fall back
to the host clock, current filesystem, live network, random defaults or a
successful no-op. Unused mandatory records also fail the case at normal exit.

`actions` is an ordered list performed between accepting the request and
returning its result:

| Action | Required fields and effect |
| --- | --- |
| `output` | `target`, `value`: write the declared output object or bounded byte range |
| `deliver` | `handler`, `arguments`: synchronously invoke a registered callback; run it to its return before the next action |
| `enqueue` | `queue`, `event`: append an event for later delivery through the owning queue/pump; does not invoke it immediately |
| `observe` | `label`: capture a named checkpoint at this exact position |
| `failure` | `code`: record provider failure; does not imply rollback or cancel subsequent explicitly listed actions |

Provider output actions specify byte offset/length when partial output matters.
Their `target` is `{stateKey,offset,length}` for bytes, with decimal-string offset/
length, or `{stateKey}` for a whole registered output value. `value` must match
that target's type and exact byte length. Provider output cannot silently grow
the target or write a different object. A `deliver` handler is a registered
operation; an `enqueue` event is a typed payload under the queue owner's schema.
Unwritten output retains its supplied previous value. Native API success does
not prove all fields initialized; failure does not prove none were written.
Model only fields the actual flagged call exposes to the provider. Do not give
an adapter unrelated game fields as implicit inputs. Reentrant deliveries may
call real game entries, replace globals or change the state a parent reads
afterward. Preserve call nesting and pre-call captures separately from live reads.

Clock records distinguish system seconds, multimedia milliseconds, game ticks
and derived conversions. Record each query and full return, even repeated equal
values. Wrap and signed deadline comparisons remain F01/P05/P10 behavior. Timer
registration, cancellation, queued expiry and callback delivery are separate
events. An idle loop's number of polls is determined by the supplied sequence,
not by how fast the implementation runs on the test machine.

Network records distinguish provider receipt, transport framing, command queue,
dispatch, authority, replies and state publication. A received packet is not
automatically a completed gameplay command. Multi-peer fixtures have one state
per peer and an explicit delivery order; clocks and queues are per endpoint
where the contract says so. Match N01–N05 routing and barriers before comparing
shared world state. Real scheduling experiments should be captured into a new
script rather than retroactively changing a deterministic fixture.

Files record opens, seek positions, short reads/writes, close/rename results and
visible partial bytes within the admitted domain. Required media/input records
capture authored content, semantic choices, completion/cancellation and relevant
network/gameplay events. Optional original-presentation records may also capture
decoded frames, sample output, palette changes, native repaint and widget events.
P05/P10 adapters declare that scope; a cosmetic callback trace is not required
for a redesigned UI, while a gameplay mutation during media completion still is.

Random inputs use §2's explicit mode. Controlled choices are valid integration
inputs; implementation-replay traces observe generated decisions and final
contexts. Only legacy-reference tests require original recurrences, seed
exchanges, discarded draws and shared presentation state. None of these modes
permits omitting required gameplay/network callbacks, mutations or candidate
attempts. X01 separately relaxes presentation-only traces and randomness.

## 5. Trace and snapshot format

Trace is a chronological array of selected event objects. Each has `seq`, `id`,
`kind`, `call`, `payload`. Seq is a consecutive metadata integer starting 0;
`id` is a unique nonempty semantic event ID, and `call` is a nonempty symbolic
invocation ID. Seq records this execution, not an identity used for matching.

Register identities by operation site, owning object/lifetime and semantic
candidate, round or attempt where relevant. Distinguish repeated occurrences
with an owner-defined occurrence key. Do not allocate IDs from global entry
order, worker scheduling, native addresses or the observed result. The same
semantic invocation/event keeps its ID across permitted schedules; repeated
or identical-valued events remain distinct. IDs cannot be reassigned after a
mismatch to make another event fit. Pure helpers may be inlined, omitted or
cached where X01 permits it: do not require invocation events for those
implementation details. Available event kinds are:

| Kind | Payload |
| --- | --- |
| `enter` | `operation`, `parent` (call ID or null), `arguments` |
| `return` | `result`; matches one entered call |
| `random` | `site`, `attempt`, `law`, `arguments`, typed `code` and `result`; replay modes also identify `context`. Optional before/after context values use that policy's registered schema. Legacy events are explicitly policy-specific. |
| `seed` | Replay-only policy/context initialization or reset, with arguments and before/after/result; never an implicit original seed requirement |
| `provider` | `stage`=`request` with input ID/operation/arguments, or `stage`=`return` with the same input ID and result; callbacks/actions appear between the pair |
| `effect` | Registered semantic effect name and named values: notice, mutation publication, command, file/network/media request, etc. |
| `snapshot` | `label`, complete declared state or explicitly identified projection |
| `stop` | `category`, `boundary`, `reason`, completed-input count and safe-prefix snapshot ID |

Each invocation's enter precedes its selected effects and child invocations;
return follows them, and final snapshot follows normal return. A stopped call
has no invented return or destructor sequence. Required synchronous callbacks
retain their nesting and actual order, including their relation to provider
output and captures/live reads. Independent sibling work can overlap only as
allowed by the registered dependencies, within its parent's lifetime. Private
worker call stacks are not extra semantic invocation events.

A fixture selects `traceKinds` for its stated comparison. Its expected trace
contains only those kinds; actual selected events must match it exactly by ID.
Omitted kinds reduce the claim and cannot hide effects required at the registered
boundary. Mandatory for the included pure mapping fixtures are enter, return
and final snapshot. A generated implementation need not materialize a code; its replay adapter may report
`code` as typed null with the mapped result and documented direct sampling law.
Controlled choices use actual codes so the mapping can be checked independently.

The event schema does not require logging every native store or pure query.
Record required effects observable to callers, callbacks, later phases and
owner-defined semantic checkpoints. An adapter must not create a new observer
between independent private updates just to demand their reference order.
Where an actual consumer distinguishes two updates, capture that observation
and retain its dependencies. A final-state-only comparison cannot prove them.
Instrumentation must neither invoke game services nor consume RNG/clock inputs;
report the executed chronology without sorting away an ordering violation.

Snapshots name stable phase boundaries, not instruction counts. Recommended
checkpoint families are:

| Family | Capture points and decisive state |
| --- | --- |
| Setup/generation | Before resolved-parameter entry; W02 land passes/contact repair/terrain/rainfall/age/rivers; pre/post poles; regions/connectivity/fertility; F05 starts and completed setup |
| Global turn | F04 before old-year global children; after each ordered child; after calendar increment/events; before civilization phases |
| Civilization/city | Upkeep entry/exit; each city in the actual scan order; both recalculations; growth/production/disorder/support/research/pollution; deletion exits; final rates/diplomacy/census |
| Units/commands | Activation, directional dispatch, each mutation child, failed/cancelled command, movement completion and recovery; no implicit active-unit reselection |
| Capture/diplomacy | Before first effect; after ownership/treasury/building/unit phases; notices and event hooks; surviving/eliminated civilization state |
| Persistence/scenario | Each F06 partial publication; S01 mode overrides; S02 matching/action passes; editor apply/cancel and serialized output |
| Multiplayer | N01 admission/handoff; N02 receive/queue/dispatch/state sections; N03 host/client barriers and timeout; N04 concealment/reveal; N05 complete and partial frames |
| Presentation/media | Information/visibility and choice boundaries, accept/cancel/skip/timeout, target changes, required completion and network/gameplay effects. Native draw/frame/palette/sample boundaries are optional reference checkpoints. |

These labels are observation opportunities, not mandatory checkpoints between
every implementation step. Register required values at real semantic boundaries;
reference-only intermediate snapshots cannot impose an internal schedule.
They are not a replacement for the owner's ordering. In particular, do not
impose a common city pass or sequential turn model on N03's distinct simultaneous paths.

## 6. Replay and comparison algorithm

1. Validate fixture syntax, typed values, hashes, registry entries and target.
   Check profile/domain and all declared dependencies. Report invalid fixtures
   separately from implementation failures; do not execute a partly installed case.
2. Create a fresh harness context, or restore the explicitly captured retained
   process state for a continuation case. Install state without game-side
   normalization. Bind every external provider to its script and initialize
   script cursors, call IDs, randomness inputs/policy and observation counters.
3. Capture entry, invoke the registered operation with supplied arguments, and
   run actual children except those explicitly declared supplied. At each provider
   request consume the next matching record and execute its actions in order.
   Emit selected observations at their actual boundaries.
4. At normal return require all mandatory environment and choice inputs consumed, record result and
   final state. At safe rejection/unknown input/fault boundary record the valid
   prefix and stop category. Never fabricate normal cleanup after a diagnostic
   stop. Harness resource cleanup occurs out of band and is not a game event.
5. Apply only the case's declared normalization mappings. Compare outcome,
   result and state by typed equality, and selected trace by the dependency
   comparison below. Compare external byte surfaces exactly after only owner-authorized masks. Stop reporting at
   the first decisive mismatch, retaining context and later differences as
   secondary diagnostics; do not resynchronize traces by dropping extra events.
6. Produce a run report with identities, input consumption, first mismatch,
   compared surfaces, masks, exclusions, evidence kind and limits. Keep the
   unchanged expected fixture; a mismatch is not permission to regenerate it.

Outcomes are `return`, `reject`, `safe-stop`, `unresolved-input`,
`unexpected-input`, `budget-exhausted` and `unavailable-evidence`. A fixture may
expect return/reject/safe-stop/unresolved-input. The last three operational
failures unexpected-input/budget-exhausted/unavailable-evidence never become
successful equivalence merely because they were anticipated. A safety case
can pass its declared safe-stop contract without being counted as an ordinary
successful gameplay case. An unresolved-input case establishes the prefix and
missing-input boundary only; it does not validate the unknown continuation.

Bounded polling/preroll loops use fixture event/provider limits and a host-time
watchdog. Budget exhaustion is inconclusive about termination. It must not
cause synthetic clock advancement, RNG draws, frames, replies or cancellation.
If the owner specifies a deliberate restrictive timeout, test that timeout as
a distinct restricted-policy operation with the actual game-clock inputs.

Allowed normalization includes mapping native allocation/handle identities to
consistent symbolic IDs, relocating known pointers into logical references, and
excluding specific padding proved unconsumed by the scoped contract. Preserve
alias identity and reuse order. Never normalize slot order, lifetime tokens,
same-policy random contexts, meaningful byte widths, signedness, failed partial output, selection
ties or known scratch values to hide a mismatch. Every exclusion names a field/
byte range, owner justification and affected claim. An exclusion record is
`{surface,selector,owner,reason}`: surface is `state`, `trace` or `bytes`, selector
names an exact registered state path/event/byte range, and owner is its document
anchor. A byte-range selector contains blob ID and decimal-string offset/length.
A normalization record is `{surface,kind,mapping,owner,reason}`; kind is
`symbolic-identity` or `original-state-adapter`, mapping names a versioned adapter
whose definition/hash is included in the evidence. Neither form can introduce
new acceptance rules not justified by the owner. X01 permits defined semantic
UI projections that exclude identified presentation-only fields/events; register
them at the boundary. No wildcard “UI differences” may hide gameplay changes,
authored-content loss, incorrect visibility, missing protocol replies or required
file bytes. Blanket nonzero-to-true conversion is not permitted.

Original same-seed maps, battle outcomes and full-session hashes are not general
acceptance oracles. When comparing independent executions, align semantic choices
and other relevant inputs, or label exact-sequence matching optional
legacy-reference. In a mixed session, compare each resolved operation with its
actual transmitted/applied result; the peers must agree on published state even
though they use different local generators.
Do not mask differences in sampled diplomatic fields, selected terrain or combat
state: those are exact under controlled choices. Original generator state and
raw consumption are outside the required RNG comparison; presentation-only
observations have the separate explicit semantic scope defined above.

Network fixtures must retain N01–N05's original operation authority, routing and
synchronization/continuation data. Identify each peer's implementation; record
RNG policy versions for cleanroom replay diagnostics without making that data a
wire requirement. Require agreement on published simulation fields at the
specified synchronization points. Required original-peer interoperability needs
actual mixed TCP/IP sessions with UDP discovery and both host/client arrangements.
Cleanroom-only peers, protocol parsing, a shared-seed lockstep substitute or an extension required by
all participants cannot establish that requirement.

In controlled-choice mode, compare random events by `(call,site,attempt)`, law,
arguments and value. Enforce owner-defined dependencies and ordering relative to
state reads, callbacks and effects; independent sample sites have no required
global order. Raw PRNG calls, prefetches and discarded samples are not trace
sites. Implementation replay additionally compares policy-local contexts and its
declared ordering guarantees. Only legacy-reference mode requires the original
complete random-event sequence. All selected trace kinds use the dependency
comparison below; this does not permit changing gameplay decisions or dropping mismatching events. Same-policy
replay additionally obeys its declared scheduling guarantees: if it promises
an exact sequence, compare that sequence too. A policy allowing multiple internal
schedules must state how its keys, contexts and captured scheduling inputs support
repeat/restore behavior; X01's relaxation cannot excuse a broken replay promise.

Exact game-state equality is distinct from file/protocol output and semantic UI
agreement. A round trip is compared to F06's specified load effects, including
lifetime renewal and mode adaptation, not to an invented identity function.
Saved UI fields follow F06 even when native windows differ. A screenshot cannot
establish hidden state or command correctness; pixel/audio equivalence is optional.
Required numeric observations still have no global floating epsilon.

### Dependency comparison

`comparison.order` is a required object with exactly `before` and `independent`.
Its lists of edges and declarations are sets for comparison; their JSON order
does not affect the dependency relation. Event-group membership is also unordered.

- `before` is an array of directed pairs `[earlierId,laterId]` over the selected
  expected events. It specifies a strict partial order; transitive consequences
  apply without redundant edges. Reject unknown IDs, self-edges, duplicate edges
  and cycles. A total-order chain is the conservative default.
- `independent` is an array of `{events,owner,reason}` declarations. `events`
  contains at least two distinct selected IDs; `owner` is an owning specification
  document/anchor, and `reason` identifies the domain and equivalence evidence.
  Every pair in a group is asserted independent. No such pair may be ordered
  by a path in `before`; reject duplicate groups (including reordered copies).
  Overlapping groups are allowed. Every pair incomparable in the transitive
  closure of `before` must occur together in at least one justified group.

Absence of an edge is not evidence of independence. Review each declaration
against the registry and X01's complete-domain rule. Reason text alone is not
a proof. A declaration may rely on a justified domain guard plus a reference
fallback, but cannot silently restrict nominal support to stock data. General
conformance additionally requires coverage of the guard's other admitted cases.

The graph must retain all registered dependencies: invocation lifetimes, data
and control dependencies, aliased/conflicting state, captured versus live reads,
selection/tie consequences, real callback nesting, failures and partial effects,
random-decision arguments/reuse, observations and publication, and required
file/network/provider order. A snapshot depends on the effects whose values it
observes and precedes later mutations it excludes. Do not add snapshots solely
to serialize unobserved private updates. Dependency review is part of fixture
review; a comparator cannot infer missing game requirements from JSON alone.

Compare as follows:

1. Validate unique IDs, selected kinds, consecutive seq values, registry identity
   rules, lifecycle and graph constraints. The expected array is one chronological
   witness: every `before` pair must agree with its seq positions. Validate every
   incomparable pair's independence declaration before running the case.
2. Filter the actual log to selected kinds, assigning consecutive seq values in
   recorded chronology. Require exactly the expected set of IDs, each once.
   Missing, extra or duplicate selected events fail; no nearest-match alignment,
   event dropping or renaming is allowed. Check identity rules and lifecycles
   against the executed operations as well as the expected registry.
3. Match events by ID and compare `kind`, `call` and `payload` by typed equality
   after only approved normalization. Seq is not compared for equality: it is
   used to check every required `before` edge in the actual log. This checks
   all transitive dependencies too. Report an offending pair and their actual
   positions when order fails. A different order inside an independent group
   is acceptable only with identical registered values and effects.
4. Independently require matching outcome, result, declared state and provider/
   choice consumption. For a stop, compare the expected valid prefix and stop
   boundary; do not demand unreached return/effect nodes. A different fault or
   earlier/later observable prefix is not masked by graph matching.

This permits different internal schedules; it does not treat every permutation
with the same final state as equivalent. Keep the actual chronological log for
diagnosis and replay. Original helper/instruction traces can remain optional
reference evidence without becoming extra baseline graph nodes.

For illustration, suppose a registration establishes two independent semantic
choices `a` and `b`: their laws, arguments, identities and eligibility are fixed
at entry, neither observes or changes the other's inputs, and both are consumed
before return. Let `e`, `r`, `x` mean enter, return and exit snapshot. The graph is:

```text
before = [[e,a], [e,b], [a,r], [b,r], [r,x]]
independent = [{events:[a,b], owner:<the owning contract>,
                reason:<the domain and independence evidence above>}]
```

This is a comparison example, not a new game operation or a complete fixture.
The placeholder owner/reason must be replaced with reviewed evidence in a case.

| Observation | Result |
| --- | --- |
| `e,a,b,r,x` or `e,b,a,r,x`, identical event identities/payloads | Accept either chronology |
| `e,a,r,b,x` | Reject: b must precede return |
| Missing b, duplicate a, extra selected event, changed choice value/arguments/call | Reject even if final state happens to match |
| Same graph with no independence declaration | Invalid fixture: the incomparable pair is unexplained |
| A group containing a and r, or an edge from r to e | Invalid fixture: claimed independence conflicts with a dependency, or the graph cycles |

For C08's pure expiry predicate or V07's pure group queries, ordinary semantic
fixtures need only the query result and real effects; omitted internal reads do
not become missing events. S03 may process independent fully backed tile edits
in a different order before its required publication. By contrast, C08 upkeep
spending, S02 late Consumed publication, W02 in-place rainfall and original-peer
messages keep the dependencies identified by their owners. Test admissible
failures, callbacks and custom data as well as nominal stock examples.

| --- | --- |
| Redesigned controls, new stock art/layout and different zoom/font choices | Same information, visibility and eligible semantic actions; equivalent game mutations and command/result payloads for the same choices. No original screenshot requirement. |
| Nominal scenario with customized names, text substitutions, graphics and media | Authored content and override identity survive; classic exported files/assets load in the original. New UI does not substitute stock content silently. |
| Cancel after committed edit; deleted/changed-owner target; remote reply or turn expiry while a dialog is open | Correct retained edits, target/actor, failure/cancel result, locks, reply and continuation; no unauthorized action or information leak. |
| Disabled/skipped/shorter media and different repaint schedules | Same semantic outcomes under aligned external decisions/events; gameplay effects occur once, network processing continues, original timeout policy remains. Cosmetic native traces need not agree. |
| Harmless font/widget/audio-device failure | Clear diagnostic or fallback, safe cleanup and coherent UI state; committed game/file effects and pending protocol obligations remain intact. |
| Malformed/truncated/unsupported input and nominal custom control cases | Documented rejection before unsupported execution; no fabricated success or corruption; ordinary custom content, sentinels, wrap and normal fragmented traffic remain accepted. |
| Omitted IPX/modem/serial/legacy lobby provider | Unavailable choice is hidden or explicit; TCP/IP/UDP, hotseat and supported file handling continue. No claim of original support being absent. |
| Score report with a different font/window size | V08/P07 use declared classic logical admission inputs for the same recalculated city prefix and score; the new renderer may display additional rows without causing additional simulation work. |
| Save through a redesigned UI and reload in original | Required UI fields remain valid/preserved or explicitly translated; no new layout metadata embedded in classic bytes. |

These are semantic/policy test requirements. Actual original-peer and file round
trips remain mandatory; passing isolated adapters does not establish interoperability.

Compare each mixed session against its own resolved actions and received state,
not the random trajectory of a separate original-only session. A random result
chosen by the designated executor is allowed to differ from that other run;
peers disagreeing about the chosen result is a failure. Private UI/knowledge and
RNG contexts need not be identical where the protocol keeps them local. Keep
packet captures and loaded-state snapshots sufficient to distinguish a valid
random outcome difference from missing publication, double execution or rerolling.

Within each applicable family cover difficulty, government, human/AI control,
mode, topology and custom-rule differences that select distinct branches. Use
pairwise combinations only where the owner's dependencies justify independence;
it cannot replace a known three-way interaction. Include equality and adjacent
boundary values, signed/high-bit/narrowed values, empty/full collections, first/
last ties and cancellation after partial effects. Do not generate arbitrary
invalid writes merely to increase numeric coverage.

For save/reload equivalence, compare a controlled uninterrupted run with a run
through the real save/load/resume path and the owner's expected differences. For
seeded continuation, restore separately captured new-policy checkpoint metadata
as well as the classic save; test original-save import with its explicit initial
random-context policy. F06 does not invent random fields in the classic file.
For network cases validate each peer's private state under its own contract and
compare the fields that must agree after publication; concealed information and
local RNG contexts need not be identical. For media cases repeat with
sound/music disabled, skips, changed cosmetic duration and missing assets; retain
semantic completion and required gameplay/network events. Include presentation-isolation runs: with the same simulation inputs
and no simulation callback differences, extra visual randomness should not
perturb simulation when the chosen policy separates those contexts. Policies
that retain sharing must record it for their own replay, not for original matching.

## 10. Current evidence limits and closure rules

The specifications state their contracts, conditions and evidence limits.
Source review and bounded fixtures do not establish complete integration or an
implemented game. Track unresolved conformance work in the table below and the
owning documents; close it only with evidence at the claimed boundary.

| Gap | Current disposition | Evidence needed for closure |
| --- | --- | --- |
| W02 original-target reconciliation | The contract pins an earlier implementation and a stable, nonmutating-callback domain | Original phase captures/full-map outputs under aligned semantic choices and other matching inputs; original seeds alone are insufficient; resolve differences without silently changing its pin |
| Native whole turns and sessions | Owner documents contain finite source checks and supplied-child cases | Independent complete F04/N03/N04 runs with real city/unit/AI/events/UI joins, retained process state and implementation decision/context traces |
| Original retained reads | Conditional inputs or bounded stops, with deliberate repairs separately identified | Producer/backing recovery or bounded original observations; do not generalize one stale value into a default |
| OOB corruption | Excluded bug under X01, including nominal assets | Safe-policy tests for valid prefix, rejected/omitted write and documented continuation; corrupt output is never an acceptance oracle |
| Save/network bytes and providers | F06/N02/N05 specify contracts; bounded checks do not cover every I/O/session path | Exact independently captured payloads, failures, partial publication and multi-peer ordering |
| Original-file interoperability | Bidirectional compatibility is required; format specifications alone do not demonstrate it | Load/play/save cycles in both engines, classic scenario/editor exports and raw maps, with absent/stale optional RNG metadata handled under F06 |
| Original-peer multiplayer | Mixed TCP/IP sessions and UDP discovery are required; different local generators/UI are permitted, original authority is retained | Actual original host/cleanroom client and reverse, sequential/simultaneous play, random-operation publication, semantic dialog responses, join/resume and host transfer in both directions without required extensions |
| Legacy/provider-dependent transports | Optional extensions under X01; recovered N05 algorithms are retained reference | Provider/environment runs only for an advertised extension; omission does not block baseline TCP/IP conformance or prove absence from the original |
| Semantic UI and content | Required information, decisions, authored content and gameplay/network effects; original raster/native traces are optional | Redesigned-interface tests at semantic boundaries, privacy/target/timeout cases, custom content and harmless-failure cleanup; optional screenshots/sample captures reported separately |
| Entry-level source coverage | The 65-family index assigns owners; exhaustive executable-entry accounting is not claimed | Versioned function/fragment ledger with caller reachability and disposition, including hand-written and library/provider edges |
| Fixture runner and corpus | Three portable specification vectors cover primitive mappings; they do not establish runtime integration | Implement adapters/comparator, independently review expected outputs, run and publish bounded reports; expand G01–G23 |

A required gap is closed only by the evidence named for it or an explicitly
narrower claim. Optional reference/provider rows are reported separately and do
not inflate required coverage or imply that required TCP/IP/UI semantics passed. Mark a fixture `captured`, `reviewed`, `passing` and `regressed` separately.
Record the tested boundary and result independently of document coverage.
A checked operation does not automatically check its entire owner document.
Record failed attempts, unavailable assets and supplied continuations without
counting them as runtime coverage.

When a discrepancy appears: locate the first differing observation; verify target,
entry state and provider schedule; classify arithmetic/order, missing input,
adapter/normalization error, implementation defect, specification defect or
excluded original bug. Resolve against independent evidence and the owning
contract. Update that owner first, then dependent fixtures and this ledger with
new revisions. Preserve old expected files and provenance in version control.

Recommended implementation order is: F01/F02 fixture import and comparison;
F03/F06/W01 state and byte adapters; bounded simulation operations; actual parent/
child joins; complete single-player sessions; UI/media, hotseat and network
integration. Do not defer randomness policy or callback semantics until after replay
has been designed: they are part of the state and trace contract from the start.
